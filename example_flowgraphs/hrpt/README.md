# HRPT examples

`hrpt_noaa_synthetic_image.grc` decodes 32 synthetic NOAA HRPT minor frames
into an image using the real `noaa_hrpt_deframer` and `hrpt_image_sink`
blocks.

## Why synthetic

A real NOAA/MetOp/Meteor HRPT or AHRPT downlink needs an L-band dish and is
recorded at a symbol rate (665.4 kbaud, biphase-coded to ~1.33 Mbaud) that made
every real recording found while adding this module multiple megabytes even
for a single scan line, with no small, freely-licensed sample available to
bundle or link to. `noaa_synthetic_symbols.bin` (~6.8 MB: 32 11,090-word minor
frames, biphase-encoded 2 symbols/bit) is generated instead, carrying a real
image -- this repo's own logo -- as the payload so the display can be checked
by eye, not just by exit code. It is hosted at this repository's own
`raw.githubusercontent.com` URL (the same pattern `droneid_mini_2.grc` uses for
its sample capture), read by a **Public HTTP Recording** block -- the one of the
three source blocks that takes a URL, where File Source takes a file on this
computer and GR World Recording takes a key into the recordings bucket. It is
not committed as a *huge* binary, so **the source block in
`hrpt_noaa_synthetic_image.grc` only resolves once this changeset is pushed to
`main`** -- before that, test locally by pointing its `url`
parameter at a `http://localhost:<port>/example_flowgraphs/hrpt/...` URL served
by a Range-capable dev server instead (`server.mjs` itself does not serve
Range requests for arbitrary static files, only `/recordings/`; see
`test_smoke.mjs`'s own note on this in AGENTS.md's recording-viewer doc).

The fixture skips `noaa_hrpt_pll_cf` and the bit slicer: this proves the new
code (the deframer's downstream consumer, `hrpt_image_sink`) end to end
without also having to get carrier-loop lock parameters right for a synthetic
signal with no real channel impairments to justify them. `noaa_hrpt_pll_cf` is
gr-hrpt's own untouched block; `test/test_lazy_scenarios.mjs`'s HRPT scenario
already constructs and wires it (with `blocks_throttle2` -> `noaa_hrpt_pll_cf`
-> `digital_binary_slicer_fb` -> `noaa_hrpt_deframer`) to cover its factory and
side-module import, which is what a real receive chain looks like.

## Regenerating the fixture

`noaa_synthetic_symbols.bin` is generated by `gen_synthetic_symbols.py`, which:
1. Resizes this repo's `editor/public/example_images/gnuradio_logo.png` to
   2048x32 greyscale and scales it to 10-bit samples.
2. Builds 32 11,090-word minor frames (one per image row): the 6 HRPT sync
   words, an ID word (spacecraft address + minor-frame number, cycling 1-4),
   and that row's pixels on AVHRR channel 2 starting at word 751
   (`hrpt_image_sink`'s default `video_start`, interleaved every 5 words).
3. Bit-serializes each word MSB-first and biphase-L encodes each bit as two
   symbols, `[1-bit, bit]` -- verified per frame against a Python port of
   `noaa_hrpt_deframer_impl.cc`'s exact bit-synchronizer state machine
   (`gr-hrpt/lib/noaa_hrpt_deframer_impl.cc`) until the decoded words round-trip
   byte-for-byte back to the input, including the channel-2 pixel row.

Run `python3 example_flowgraphs/hrpt/gen_synthetic_symbols.py` (needs `numpy`
and `Pillow`) to regenerate it with a different image, line count or channel;
the round-trip assertion against the ported state machine is what guarantees
the fixture actually plays back through the real block rather than merely
looking plausible.
